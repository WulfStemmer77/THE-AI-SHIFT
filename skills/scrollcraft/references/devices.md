# Device kit

Use devices per narrative beat. A device is what the visitor's input changes.

## scrub
Scroll controls a pre-rendered clip or image sequence.
Use for: hero camera move, assembly, macro detail.
Avoid more than two heavy scrub acts on a typical page.

## pin
Stage stays fixed while content/state advances.
Use for: argument, technical explanation, progressive annotations.

## pan
Vertical scroll drives horizontal travel.
Use for: model lineup, options, timeline, gallery.
Ensure real overflow exists at every target viewport.

## reveal
Clip-path/mask/wipe reveals another state.
Use for: before/after, raw/finished, internal/external, layer exposure.

## parallax
Different depth planes move at different rates.
Use for: restrained spatial depth, not as a substitute for composition.

## kinetic type
Lines/words/characters assemble or transform.
Use sparingly and only when type is part of the concept.

## drift
Page or stage ground evolves through controlled color/light states.
Use to mark emotional chapters or environment changes.

## pointer response
Pointer/touch changes tilt, spotlight, focus, or object state.
Use for local exploration; never make essential information mouse-only.

## real 3D
Scroll or pointer changes camera/object state in WebGL.
Use only when real interaction earns the rendering cost.

## flow
Normal document flow with subtle in-view transitions.
Use when the reader needs substance and calm. Not every section should be pinned.

## Cue contract

For progress-driven cues, use an explicit window:

`from, to, ramp-in, ramp-out`

Ensure important text has a real plateau at full opacity. The final CTA/statement must resolve and remain visible at the end.
